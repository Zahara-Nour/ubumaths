> Pour représenter des expressions mathématiques, on a créé un AST 
(@docs/ref/mathAST) et un systeme d'unité @src/lib/mathAST/units/ qui doit 
servir de pivot entre deux syntaxes : latex qui n'est pas tres lisible mais 
qui est completement pris en charge par le compute engine de mathlive, et 
une syntaxe custom proche de ASCII Math. Le parser latex 
(@src/lib/mathAST/parser/latex/)a déjà été créé et va servir de référence 
pour implémenter le parser de notre syntaxe custom. Voici les 
caractéristique de la syntaxe custom.

- espaces : non significatifs

- gestion des erreurs : mode strict ou tolerant comme pour le parseur latex

- Précédence (basse → haute):
  1. Relations:     = < > <= >= != <=> => (les relations peuvent être 
chainées comme a < b < c)
  2. Addition/Soustraction:  +  -
  3. Multiplication (* et implicite), Division (:) 
  4. Puissance:  ^ 
  5. Opérateur Unaire: - et +
  6. Subscript: _
  7. Atomes:  nombres, variables, fonctions, délimiteurs, fractions(/ ou 
:/), symboles

- Addociativité : gauche pour addition, soustraction, multiplication, 
division ; droite pour puissance

- Entrées clavier : ASCII uniquement (pas d'unicode)

- Style : inspirée d'ASCII Math (https://asciimath.org)

- nombres : accepter . et , comme séparateur de partie décimale et partie 
entière

- variables : 1 seule lettre

- fonctions : cos, sin, tan, ln, log, exp, sqrt, sqrt[n]. support des 
écritures comme sin^2(x) ou log_2(x)

- délimiteurs : dans la syntaxe, il y en a que 2. Les parenthèses (), et {} 
qui disparait dans l'AST (il ne sert qu'à éviter l'ambiguité sur des 
expressions du style {3+x}/{5+x} sans avoir à rajouter des parenthèses qui 
n'ont pas lieu d'être dans les fractions)

- couleurs (à implémenter avec une pile de couleur, le balisage doit être 
transparent par rapport à la structure de l'expression): 
      @red{x}           // nom
      @#FF5500{x}       // hex avec #

- unités : [unit]  (@src/lib/mathAST/units/ pour voir la syntaxe des unités 
et le parser spécifique aux unités) 


- choix :
  cette syntaxe doit rester simple pour être lisible mais assez complexe 
pour pouvoir exprimer des choses intéressantes
  on doit pouvoir round-trip vers LaTeX sans perte d'information
 Faire deux versions de parser comme pour le parser-latex : un pratt et un 
RD, dans 2 fichiers différents.  

- syntaxes particulières : 
  2+3/4+5 représente 2+Fraction(3;4)+5
  {2+3}/{4+5} représente Fraction(2+3;4+5)
  (2+3)/(4+5) représente Fraction((2+3);(4+5))
  pour les puissances, sauf exposants simples (par exemple 2 ou a) , il faut
 entourer l'exposant par des {} : x^{-2}, x^{3+4}

- traduction dans l'AST :
 division : -> DivisionNode avec displayStyle: 'ratio'
 fraction / -> DivisionNode avec displayStyle: 'fraction'
 fraction :/ -> DivisionNode avec displayStyle: 'inline'
 multiplication * -> MultiplicationNode avec displayStyle : 'cross'
 multiplication implicite (détection automatique) -> MultiplicationNode avec
 displayStyle : 'implicit'

  ---
  Récapitulatif - Syntaxe Custom MathAST

  Pré-traitement

  - Espaces : retirés avant parsing

  Atomes

  - Nombres : . ou , comme séparateur décimal (3.14, 3,14)
  - Variables : 1 seule lettre (x, a)
  - Symboles : \pi, \alpha, \beta, \gamma, \theta, \infty

  Opérateurs (précédence croissante)

  1. Relations : = < > <= >= != <=> =>
  2. Addition : +, -
  3. Multiplication : * (cross), implicite, : (ratio), / (fraction), :/
  (inline)
  4. Puissance : ^ (droite-associatif)
  5. Unaire : -, +
  6. Subscript : _

  Multiplication implicite

  - ✅ 2x, xy, 2(x), (a)(b), sin(x)cos(x)
  - ❌ x2, (a)2

  Fractions

  - 3/4 → fraction simple
  - {2+3}/{4+5} → fraction groupée ({} transparent)
  - (2+3)/(4+5) → fraction avec parens visibles

  Subscripts/Superscripts

  - Nombres groupés : x_12, x^12 OK
  - Lettres non groupées : x_ab, x^ab erreur → utiliser x_{ab}, x^{ab}
  - Exposant négatif : x^{-2} (pas x^-2)

  Fonctions

  - Set : sin, cos, tan, ln, log, exp, sqrt
  - Parenthèses obligatoires : sin(x) ✅, sin x ❌
  - Puissance : sin^2(x) → FunctionNode.power, sin(x)^2 → SuperscriptNode
  - Racine n-ième : sqrt[3](x)

  Valeur absolue

  - |x| → FunctionNode(abs)

  Unités

  - 5[m/s], (2+3)[kg]
  - S'attache au dernier atome : 2+3[m] = 2 + 3[m]

  Couleurs

  - @red{...}, @#FF5500{...}
  - Imbrication OK : @red{x + @blue{y}}
  - Set : CSS + xcolor (comme LaTeX parser)

  Délimiteurs

  - () → visible dans l'AST
  - {} → groupement transparent
  - [] → réservé (unités, sqrt[n])

  Edge cases

  - +5 → PositiveNode ✅
  - --5 → erreur ❌
  - () → erreur ❌

  1. \frac{a}{b} (commande LaTeX) → parsé au niveau primary (atome)
