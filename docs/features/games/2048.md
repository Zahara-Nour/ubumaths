## Vue d'ensemble

Le jeu 2048 est un puzzle mathématique où le joueur doit combiner des tuiles de même valeur pour atteindre la tuile **2048**. Cette implémentation UbuMaths ajoute une dimension éducative avec l'affichage optionnel des **puissances de 2**.

### Objectifs Pédagogiques

- **Comprendre les puissances de 2** : Visualiser que 64 = 2⁶, 1024 = 2¹⁰, 2048 = 2¹¹
- **Croissance exponentielle** : Expérimenter comment les valeurs doublent à chaque fusion
- **Stratégie et planification** : Développer la pensée anticipative et la résolution de problèmes

### Public Cible

- **Élèves** : Tous niveaux (accessible aux invités, score sauvegardé pour les étudiants authentifiés)
- **Enseignants** : Peuvent consulter les performances de leurs élèves via le classement
- **Tous** : Jeu accessible sans authentification (scores en localStorage)

## Comment Jouer

### Objectif

Atteindre la tuile **2048** en fusionnant des tuiles de même valeur.

### Règles

1. **Mouvement** : Chaque commande (flèche ou swipe) déplace **toutes** les tuiles dans la direction choisie
2. **Fusion** : Deux tuiles **identiques** qui se touchent fusionnent en une seule
   - 2 + 2 = 4
   - 4 + 4 = 8
   - 8 + 8 = 16
   - ... jusqu'à 2048 et au-delà
3. **Nouvelle tuile** : Après chaque mouvement valide, une tuile 2 ou 4 apparaît dans une case vide
4. **Mouvement invalide** : Si aucun déplacement ou fusion n'est possible, le mouvement est ignoré

### Conditions de Fin

- **Victoire** : Une tuile atteint la valeur **2048**
  - Option de continuer pour atteindre 4096, 8192, etc.
- **Défaite** : Grille pleine ET aucune fusion possible

### Stratégies Recommandées

- **Coin Strategy** : Gardez vos tuiles de grande valeur dans un coin (ex: coin inférieur gauche)
- **Chaîne Ordonnée** : Construisez des rangées/colonnes en ordre croissant
- **Évitez la Saturation** : Ne remplissez pas complètement la grille
- **Anticipation** : Pensez 2-3 coups à l'avance

## Mode Éducatif

### Qu'est-ce que la Notation en Puissances ?

Toutes les valeurs du jeu 2048 sont des **puissances de 2** :

| Valeur   | Puissance | Notation  |
| -------- | --------- | --------- |
| 2        | 2¹        | `2¹`      |
| 4        | 2²        | `2²`      |
| 8        | 2³        | `2³`      |
| 16       | 2⁴        | `2⁴`      |
| 32       | 2⁵        | `2⁵`      |
| 64       | 2⁶        | `2⁶`      |
| 128      | 2⁷        | `2⁷`      |
| 256      | 2⁸        | `2⁸`      |
| 512      | 2⁹        | `2⁹`      |
| 1024     | 2¹⁰       | `2¹⁰`     |
| **2048** | **2¹¹**   | **`2¹¹`** |
| 4096     | 2¹²       | `2¹²`     |
| 8192     | 2¹³       | `2¹³`     |

### Comment Activer le Mode Éducatif

1. Cochez la case **"Afficher les puissances"** au-dessus du plateau de jeu
2. Les tuiles de valeur ≥ 4 afficheront leur notation en exposant
3. Exemple : La tuile `64` affichera :
   ```
   64
   2⁶
   ```

### Objectif d'Apprentissage

- **Visualiser** la croissance exponentielle
- **Comprendre** que chaque fusion multiplie par 2 → exposant +1
  - 2⁵ × 2 = 2⁶ (32 × 2 = 64)
  - 2⁶ + 2⁶ = 2⁷ (64 + 64 = 128)
- **Pratiquer** le calcul mental avec les puissances de 2

## Système de Scores

### Calcul du Score

Le score est calculé en **additionnant les valeurs fusionnées** :

- Fusion 2 + 2 = 4 → Score +4
- Fusion 4 + 4 = 8 → Score +8
- Fusion 64 + 64 = 128 → Score +128
- etc.

**Score Théorique Maximum** : ~3 932 100 (pour atteindre une tuile unique de 131 072 = 2¹⁷)

### Sauvegarde des Scores

#### Pour les Invités (Non Authentifiés)

- **Stockage** : localStorage du navigateur (`2048-best-score`)
- **Persistance** : Tant que le cache n'est pas effacé
- **Limitations** : Local au navigateur, non synchronisé

#### Pour les Étudiants (Authentifiés)

- **Stockage** : Table `game_2048_scores` dans Supabase
- **Mise à jour** : Automatique après chaque partie (POST à `/api/games/2048/scores`)
- **Données Sauvegardées** :
  - Meilleur score (`best_score`)
  - Nombre de parties jouées (`games_played`)
  - Nombre de fois que 2048 a été atteint (`tiles_2048_reached`)
  - Nombre de fois que 4096 a été atteint (`tiles_4096_reached`)

### Classement (Leaderboard)

- **Accessible à** : Tous les utilisateurs authentifiés (étudiants, enseignants, admins)
- **Endpoint** : `GET /api/games/2048/leaderboard?limit=10`
- **Tri** : Par `best_score` décroissant
- **Affichage** :
  - Rang (1, 2, 3, ...)
  - Nom de l'utilisateur
  - Avatar
  - Meilleur score
  - Parties jouées
  - Statistiques 2048/4096

### Pure Function Game Logic

All game logic is implemented as **pure functions** in `game-logic.ts`:

#### Core Functions

```typescript
// Initialize new game with 2 random tiles
export function initializeBoard(): GameState;

// Perform move in specified direction
export function move(state: GameState, direction: Direction): GameState;

// Add random tile (2 or 4) to empty cell
export function addRandomTile(board: GameBoard): GameBoard;

// Move and merge tiles in a single row
export function moveTilesInRow(row: (Tile | null)[]): {
	row: (Tile | null)[];
	scoreGain: number;
	merges: boolean;
};

// Check win/lose conditions
export function isGameWon(board: GameBoard): boolean;
export function isGameOver(board: GameBoard): boolean;
```

#### Movement Algorithm

1. **Rotate board** so that direction becomes "left"
   - `left` → 0 rotations
   - `up` → 1 counter-clockwise rotation
   - `down` → 1 clockwise rotation
   - `right` → 2 rotations (180°)

2. **Move all rows left** using `moveTilesInRow()`
   - Extract non-null tiles
   - Merge adjacent tiles with same value
   - Pad with nulls

3. **Rotate back** to original orientation

4. **Add random tile** if board changed

5. **Update game state** (score, won, gameOver)

**Why Rotation?** Simplifies logic by reducing 4 directions to 1 implementation.

#### Animation Types

1. **Movement** : `transform` transition (150ms cubic-bezier)
   - GPU-accelerated via `translate()`
   - Applied only to non-new, non-merged tiles

2. **Appearance** : `tile-appear` keyframe (200ms ease-out)
   - Scale from 0 to 1
   - Opacity from 0 to 1
   - Applied to tiles with `isNew: true`

3. **Merge** : `tile-merge` keyframe (300ms ease-in-out)
   - Pulse effect: scale 1 → 1.1 → 1
   - Applied to tiles with `mergedFrom` array

#### Performance Optimizations

- **Absolute Positioning** : Tiles positioned absolutely for smooth animations
- **Transform Over Position** : Uses `transform: translate()` instead of `left`/`top`
- **Separate Transition Timings** : Color changes (200ms) separate from movement (150ms)
- **Accessibility** : `@media (prefers-reduced-motion)` disables all animations

## API Endpoints

### `POST /api/games/2048/scores`

Submits a new game score for the current user.

#### Authentication

- **Required**: Yes (student only)
- **Role**: `student`

#### Request Body

```typescript
{
  score: number,           // Final score (0 - 4,000,000)
  reached_2048: boolean,   // Did player reach 2048 tile?
  reached_4096: boolean    // Did player reach 4096 tile?
}
```

#### Zod Validation Schema

```typescript
const submit2048ScoreSchema = z
	.object({
		score: z
			.number()
			.int('Score must be an integer')
			.min(0, 'Score cannot be negative')
			.max(4_000_000, 'Score exceeds maximum possible value')
			.finite('Score must be a finite number'),
		reached_2048: z.boolean(),
		reached_4096: z.boolean()
	})
	.refine(
		(data) => {
			// Business logic: must reach 2048 before 4096
			if (data.reached_4096 && !data.reached_2048) {
				return false;
			}
			return true;
		},
		{
			message: 'Invalid tile progression: cannot reach 4096 without reaching 2048 first'
		}
	);
```

#### Logic

1. **Check for existing record** for `user_id`
2. **If no record** → INSERT new row
   - `best_score = score`
   - `games_played = 1`
   - `tiles_2048_reached = reached_2048 ? 1 : 0`
   - `tiles_4096_reached = reached_4096 ? 1 : 0`
3. **If record exists** → UPDATE
   - `best_score = max(current_best, new_score)`
   - `games_played += 1`
   - `tiles_2048_reached += reached_2048 ? 1 : 0`
   - `tiles_4096_reached += reached_4096 ? 1 : 0`

#### Response

```typescript
{
  success: true,
  best_score: number,      // Updated best score
  is_new_best: boolean,    // True if new personal best
  games_played: number     // Updated total games played
}
```

#### Error Responses

- `400` : Invalid request body (Zod validation failure)
- `401` : Not authenticated
- `403` : Not a student
- `500` : Database error

```typescript
const leaderboard2048QuerySchema = z.object({
	limit: z
		.string()
		.optional()
		.default('10')
```

## Database Schema

### Table: `game_2048_scores`

Stores user scores and statistics for the 2048 game (one row per user).

#### Columns

| Column               | Type        | Constraints                                             | Description                       |
| -------------------- | ----------- | ------------------------------------------------------- | --------------------------------- |
| `id`                 | UUID        | PRIMARY KEY, DEFAULT gen_random_uuid()                  | Unique identifier                 |
| `user_id`            | UUID        | NOT NULL, UNIQUE, FK → auth.users(id) ON DELETE CASCADE | User reference (one row per user) |
| `best_score`         | INTEGER     | NOT NULL, DEFAULT 0, CHECK ≥ 0                          | Highest score achieved            |
| `games_played`       | INTEGER     | NOT NULL, DEFAULT 0, CHECK ≥ 0                          | Total number of games played      |
| `tiles_2048_reached` | INTEGER     | NOT NULL, DEFAULT 0, CHECK ≥ 0                          | Count of times reached 2048 tile  |
| `tiles_4096_reached` | INTEGER     | NOT NULL, DEFAULT 0, CHECK ≥ 0                          | Count of times reached 4096 tile  |
| `created_at`         | TIMESTAMPTZ | NOT NULL, DEFAULT NOW()                                 | First play timestamp              |
| `updated_at`         | TIMESTAMPTZ | NOT NULL, DEFAULT NOW()                                 | Last score update timestamp       |

#### Constraints

- **PRIMARY KEY** : `id`
- **UNIQUE** : `user_id` (one row per user)
- **FOREIGN KEY** : `user_id` → `auth.users(id)` ON DELETE CASCADE
- **CHECK** : All numeric fields ≥ 0

#### Indexes

1. **Automatic Indexes** :
   - PRIMARY KEY on `id`
   - UNIQUE constraint on `user_id`

2. **Custom Indexes** :
   - `idx_2048_scores_leaderboard` : `best_score DESC` (for leaderboard queries)
   - `idx_2048_scores_recent` : `updated_at DESC` (for recent activity)

#### RLS Policies

Row Level Security (RLS) is **enabled** with 3 policies:

##### 1. View Leaderboard (SELECT)

```sql
CREATE POLICY "Authenticated users can view 2048 leaderboard"
ON public.game_2048_scores
FOR SELECT
TO authenticated
USING (true);
```

- **Who**: All authenticated users (students, teachers, admins)
- **What**: Can view all scores (leaderboard is public)

##### 2. Insert Own Scores (INSERT)

```sql
CREATE POLICY "Students can insert own 2048 scores"
ON public.game_2048_scores
FOR INSERT
TO authenticated
WITH CHECK (
  auth.uid() = user_id
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE profiles.id = auth.uid()
    AND profiles.role = 'student'
  )
);
```

- **Who**: Students only
- **What**: Can insert only their own score (one row per user)

##### 3. Update Own Scores (UPDATE)

```sql
CREATE POLICY "Students can update own 2048 scores"
ON public.game_2048_scores
FOR UPDATE
TO authenticated
USING (
  auth.uid() = user_id
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE profiles.id = auth.uid()
    AND profiles.role = 'student'
  )
)
WITH CHECK (
  auth.uid() = user_id
  AND EXISTS (
    SELECT 1 FROM public.profiles
    WHERE profiles.id = auth.uid()
    AND profiles.role = 'student'
  )
);
```

- **Who**: Students only
- **What**: Can update only their own score

##### Auto-Update `updated_at`

```sql
CREATE TRIGGER trigger_update_2048_scores_updated_at
```

Automatically updates `updated_at` timestamp on row modification.

### Performance Optimization Tips

1. **Avoid Re-renders** : Use `$derived` for computed values instead of `$effect`

   ```typescript
   // ✅ Good
   let activeTiles = $derived(gameState.board.flat().filter((t): t is Tile => t !== null));

   // ❌ Bad - triggers effect on every board change
   let activeTiles = $state<Tile[]>([]);
   $effect(() => {
   	activeTiles = gameState.board.flat().filter((t): t is Tile => t !== null);
   });
   ```

2. **Memoize Expensive Functions** : Use Svelte 5 `$derived` for calculations
3. **Use CSS Transforms** : Always prefer `transform: translate()` over `left`/`top`
4. **Debounce API Calls** : Wait until game is finished before calling score API
5. **Lazy Load Confetti** : Only import `canvas-confetti` when victory occurs

### Common Pitfalls

#### ❌ Mutating Game State

```typescript
// ❌ WRONG - Mutates existing state
gameState.score += 10;
gameState.board[0][0] = newTile;

// ✅ CORRECT - Create new state
gameState = {
	...gameState,
	score: gameState.score + 10,
	board: gameState.board.map((row) => [...row])
};
```

#### ❌ Forgetting Zod Validation

```typescript
// ❌ WRONG - No validation
const body = await request.json();
const { score } = body;

// ✅ CORRECT - Always validate
const body = await request.json();
const validation = submit2048ScoreSchema.safeParse(body);
if (!validation.success) {
	throw error(400, validation.error.issues[0].message);
}
const { score } = validation.data;
```

#### ❌ Not Handling SSR

```typescript
// ❌ WRONG - Crashes on server
let bestScore = parseInt(localStorage.getItem('2048-best-score'));

// ✅ CORRECT - Check browser environment
import { browser } from '$app/environment';
let bestScore = $state(browser ? parseInt(localStorage.getItem('2048-best-score') || '0') : 0);
```
