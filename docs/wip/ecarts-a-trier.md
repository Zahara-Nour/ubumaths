# Écarts de la doc système, triés en chantiers

> **Date** : 2026-10-10. **Source** : les sections d'écarts de toutes les docs de
> [docs/systeme/](../systeme/) (« Écarts connus », « Doutes », « Points ouverts », « Lacunes »,
> « Limites », « Pièges », « État »), plus [atelier-progress.md](atelier-progress.md) §Dettes.
> **Méthode** : lecture de chaque section ; retrait de ce que couvre déjà
> [rgpd-securite-constats.md](rgpd-securite-constats.md) (session RGPD dédiée) ; dédoublonnage ;
> une nature par écart ; les « Bug visible » re-vérifiés dans le code le jour même (grep, lecture,
> et deux mesures par test temporaire supprimé aussitôt). Rien n'a été corrigé.
>
> Natures : **V** bug visible · **L** bug latent · **M** code mort · **C** commentaire ou message
> périmé · **D** décision produit. Effort : **S** < 1 h · **M** ≈ demi-journée · **L** > 1 jour.
> Provenance : « vérifié » = mesuré ou vérifié par la doc source ou par ce tri ; « déduit » = lu
> dans le code, jamais exécuté.

**Bilan** : ~125 entrées lues (backlog Python compté pour une) ; 9 doublons fusionnés ; retirés :
9 déjà dans les constats RGPD, 5 corrigés depuis (dont V12), 7 non retenus → **72 écarts classés** :
12 V (dont V12, plus vrai), 14 L, 20 M, 15 C, 11 D — plus **15 à transmettre** à la session RGPD.
Mise à jour du 2026-10-10 : K2 fait (V7, L5, L6, C8 retirés) ; V13 et L15 ajoutés (relevés en
le faisant).
